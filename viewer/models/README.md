# 차량 3D 모델 (STL)

STL 파일을 이 폴더에 넣고 `models.json` 에 항목을 추가하면 뷰어가 박스 차량 대신
그 모델을 씁니다. **파일이 없으면 자동으로 저폴리 박스로 폴백**하므로, 모델을
구하기 전에도 개발과 시연에 지장이 없습니다.

## 크기를 몰라도 됩니다

STL 은 단위 정보를 담지 않습니다 (mm 로 만든 파일도 있고 m 로 만든 파일도 있습니다).
그래서 뷰어는 **바운딩 박스를 재서 실제 전장에 맞춥니다.**

```json
{
  "models": {
    "sedan_a": {
      "file": "sedan_a.stl",
      "autoFitLength": 4.7,
      "upAxis": "Z",
      "headingOffsetDeg": 90,
      "pivot": "rear_axle"
    }
  }
}
```

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `file` | 이 폴더 안의 STL 파일 이름 | (필수) |
| `autoFitLength` | 이 차량의 실제 전장(m). 바운딩 박스를 여기에 맞춰 스케일 | `4.7` |
| `upAxis` | STL 의 위쪽 축. CAD 출력물은 대개 `"Z"` | `"Y"` |
| `headingOffsetDeg` | 모델이 향한 방향 보정. 차가 옆을 보면 `90` 또는 `-90` | `0` |
| `pivot` | `"rear_axle"` 이면 원점을 뒷축 중심으로 (자전거 모델 기준점과 일치) | `"center"` |
| `scaleOverride` | 자동 맞춤을 무시하고 배율을 직접 지정 | `null` |
| `offset` | 미세 위치 보정 `[x, y, z]` (m) | `[0,0,0]` |

## 맞추는 순서

1. STL 을 넣고 `models.json` 에 `file` 과 `autoFitLength` 만 적는다
2. 새로고침해서 본다
3. 차가 옆이나 뒤를 보면 → `headingOffsetDeg` 를 90 / 180 / -90 중에서 고른다
4. 차가 눕거나 바닥에 파묻히면 → `upAxis` 를 `"Z"` 로 바꾼다
5. 회전할 때 축이 이상하면 → `pivot` 을 `"rear_axle"` 로

## 파일 크기

STL 은 저장소에 함께 커밋합니다 (다른 세션도 같은 화면을 봐야 하므로).
단, 단일 파일이 **50MB 를 넘으면** GitHub 이 경고하고 100MB 면 거부하므로,
그 전에 폴리곤을 줄이거나 Git LFS 로 전환하세요.

저폴리(1~5만 삼각형)로 충분합니다. 탑다운 시점에서는 차이가 거의 안 보이고,
120대를 동시에 그려야 하므로 가벼운 편이 낫습니다.
